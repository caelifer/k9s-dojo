# Notes
# - telemetrygen takes one signal per invocation, so the pod runs three
#   containers: traces, metrics, logs. They fail independently, which is exactly
#   what the per-container RESTARTS column in `:pod` is for.
# - `--otlp-insecure` is required in-cluster because the collector terminates
#   plaintext on 4317; `--duration 1h` plus the restart policy keeps load on.
# - Cluster telemetry is two different problems: kube-state-metrics turns API
#   objects into metrics (needs RBAC: list/watch on pods, nodes, workloads), and
#   node-exporter turns host counters into metrics (needs hostPath mounts and a
#   toleration for every taint, or the system pool is invisible).
# - The collector needs a `prometheus` receiver for both, and the metrics
#   pipeline must list both receivers: `receivers: [otlp, prometheus]`.
# - On this simulated cluster no pod actually runs, so nothing lands in
#   Loki/Tempo/Mimir. On a real cluster the checks that matter are
#   `kubectl -n pipeline logs deploy/kube-state-metrics` for a successful scrape
#   and the `up` metric in Grafana's Mimir datasource.
